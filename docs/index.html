Domínio Core

Módulos altamente desacoplados construídos para suportar alto tráfego e regras de negócio complexas de uma oficina mecânica.

Gestão de Clientes

Suporte para PF e PJ, com validações complexas de documentos (CPF/CNPJ) implementadas como Value Objects.

Controle de Veículos

Vínculo cliente-veículo com suporte flexível a formatos de placas antigos e do padrão Mercosul.

Ordem de Serviço (O.S.)

Coração do sistema. Rastreamento de status, integração com serviços, consumo de peças e insumos.

Gestão de Estoque

Rastreio completo do histórico. Entradas, saídas, ajustes e devoluções garantindo integridade de dados.

Autenticação JWT

Segurança robusta baseada em Roles (Administrador, Funcionário) com tokens de 8h de expiração via HMAC SHA256.

Paginação Nativa

Respostas HTTP 206 (Partial Content) para listagens volumosas, otimizando latência e banda de rede.

Design Pattern

Arquitetura Limpa
& DDD

O sistema foi construído em 4 camadas distintas, garantindo que as regras de negócio permaneçam agnósticas a frameworks ou banco de dados.

  • Repository & Unit of Work Coordenação transacional segura para o Entity Framework Core.
  • Command Result Pattern Padronização de retornos da API contendo Dados, Mensagens e Status HTTP.
  • DTO Pattern Isolamento total entre o modelo de domínio (Entities) e a exposição externa via API.

Fase 3

Infraestrutura & DevOps

Do container ao cluster: conteinerização, orquestração, infraestrutura como código, borda de autenticação serverless e observabilidade — provisionadas na AWS (API Gateway + Lambda, EKS, RDS) e monitoradas via Datadog.

Conteinerização

Dockerfile multi-stage (build + runtime) e docker-compose.yml com SQL Server para desenvolvimento local.

Kubernetes

Deployment (2 réplicas), Service NodePort, ConfigMap/Secret e HPA (2-6 réplicas por CPU 70%/memória 80%) em /k8s.

Auth Serverless

API Gateway HTTP API + Lambda (.NET 8) que valida CPF e emite JWT, e Lambda authorizer que protege as rotas /api/* — repositório TechChallenger.auth.

Terraform (IaC)

Provisiona VPC, cluster EKS e ECR (TechChallenger.k8s) e o RDS SQL Server (TechChallenger.db) — segregado por domínio, um repo por infra.

CI/CD

GitHub Actions em cada um dos 4 repositórios: build, testes, build/push da imagem, migration do banco e deploy automatizado a cada push em main.

Observabilidade (Datadog)

Agent DaemonSet no EKS (APM, DogStatsD, logs) + Log Forwarder para a camada serverless — traces, logs correlacionados (dd.trace_id) e métricas de negócio customizadas por status de OS.

Estrutura do Tech Challenge

Os 4 Repositórios

A solução é segregada em 4 repositórios independentes, cada um com CI/CD próprio, conforme exigido pela rubrica da Fase 3.

TechChallenge (este repositório)

API principal em Clean Architecture, rodando em Kubernetes (EKS) com HPA, instrumentada com Datadog.

TechChallenger.auth

API Gateway HTTP API + Function Serverless (.NET 8) que valida CPF, consulta o cliente e emite o JWT; inclui o Lambda authorizer.

TechChallenger.db

Terraform puro provisionando o banco gerenciado — RDS SQL Server Express — na mesma VPC do cluster.

TechChallenger.k8s

Terraform puro provisionando VPC, subnets, cluster EKS + Node Group, ECR e metrics-server (via Helm).
